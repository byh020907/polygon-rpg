공식 게임 위키 · 현재 제품 명세

D-30, 고대 병기보다 먼저 왕국의 다섯 기계를 구한다

동네 고물상 견습생인 플레이어는 라이벌 견습생을 구조하려고 폐병기의 제어핵을 떼어낸 결과 고대 병기를 비상 운용으로 깨운다. 현재의 검·방패 액션 감각을 유지한 채, 한 달 동안 다섯 대지역을 교차해 동원 신호로 오작동한 생활 설비의 군수 인장을 해제하고 산업기계를 대항 병기의 부품으로 바꾸어 수도 파괴를 막은 뒤 자신이 일으킨 사고의 책임까지 마무리한다.

1. 게임 개요

생활형 산업 왕국을 무대로 한 2D 액션 RPG. 작은 캐릭터로 넓은 작업 현장을 탐험하고, 검·방패 기본기의 손맛과 D-30 자유 캠페인의 선택을 함께 경험한다.

플레이어와 목표 경험

Target Player

짧고 깊은 기본기 액션, 눈에 보이는 준비, 자유로운 공략 순서와 가벼운 재난 모험을 선호하는 2D action RPG 플레이어.

Desired Outcome

플레이어는 약 10시간 동안 반복 등장하는 사람들과 다섯 지역을 오가며 매 행동의 시간값과 고대 병기의 진로를 읽고, 구조를 위해 내린 첫 선택부터 지역 주민을 도운 결과까지 맵·관계·로봇 외형·전투 선택에 쌓이는 자신만의 한 달을 완성한다.

기본 문법과 Polygon RPG의 변화
레오곡 baseline 유지하는 경험 Polygon RPG Delta
2D 액션 RPG·장비·전투 무기/방어구/도구, 속도·stamina·공격 성격, 가드/그로기 독립 방패, 현장 절단/방호 역할, 같은 입력의 장비 조합
거점·탐험·성장 상점/제작/강화/인챈트, 퀘스트, 돈/재료, 날짜 압박 수거·복구 소재, 5지역 자유 순서, D-30와 산업기계 조립
단순한 외형과 손맛 읽히는 실루엣과 조작 피드백 밝은 플랫 산업 세계, 작은 인물·넓은 공간, 개선된 동작/광원

기본 시스템을 이유 없이 다시 발명하지 않는다. baseline에서 유지할 것과 Human이 정한 차이를 먼저 구분한다.

2. 세계관과 도입

오래된 설비를 고치고 이어 붙이며 생업을 이어가는 생활형 산업 왕국이다. 낡음은 멸망, 고철은 쓰레기, 산업기계는 디스토피아가 아니다. 군수 인장은 생활 기계에 남은 옛 잠금·접속 규격이다.

PG-SCRAP-AWAKENING

사람을 구하려 내린 선택으로 고대 병기를 깨우는 20~30분 도입을 플레이한다

  • 새 게임은 고물상 주인의 정식 수거 의뢰와 인물 소개 → 동년배 라이벌 견습생과 현장 이동 → 기본 탐색·전투 → 붕괴 사고 → 구조 요청 → 주인공 독백과 제어핵 조사 → 핵 회수·구조 성공 → 고대 병기 각성 → 마을 귀환의 약 20~30분 실제 플레이로 진행한다.
  • 폐병기의 자동 회수팔이 라이벌을 붙잡아 끌고 가며, 회수팔과 직접 연결된 제어핵을 떼어 정상 제어를 끊는 것만이 구조 방법이다. 회수 전 라이벌의 구조 요청과 현장 상태를 머리 위 말풍선으로, 위험과 선택 이유를 주인공 머리 위 짧은 독백으로 보여 주며 값나가 보여 줍는 동기로 대체하지 않는다.
  • 장치 회수로 구조가 성공한 직후 입력 잠금, 카메라 이동, 눈 점등, 부품 결합과 화면 흔들림과 비상 장갑 안으로 봉쇄되는 접속부로 불완전한 고대 병기의 각성을 보여 준다.
  • 왕도 도착까지 D-30을 표시한 뒤 조작을 돌려주며 제어핵은 이후 대항 병기의 두뇌가 된다. 고대 병기는 제어핵 위치가 아니라 저장된 중앙 지휘소 좌표를 따른다.
  • 고물상 주인은 고물상 내부에서 장치를 분석하고 왕국 지도와 차고문을 열어 미완성 골격·완성도 0%를 보여 준다. 인물의 태도는 “퇴직했는데 또 야근”처럼 가볍다.
  • 라이벌은 구조 뒤 사라지지 않고 좋은 부품을 두고 경쟁하면서도 주인공에게 빚을 진 반복 정찰 인물로 남아 여러 지역을 먼저 돌며 소문·경로·새 사건을 가져온다.

3. 주요 인물

인물 현장 역할 그림과 행동으로 보여 주는 것
주인공 안전 확보·위험 기계 제압 현장 절단검과 방호판, 작업복과 수리 흔적
라이벌 탐색·측량·선점·회수 갈고리/측량 장비, 조사·현장 이동
고물상인 전직 현장 수거·복구반 장비 취급·현장 지식·작업장 공구

같은 교육을 받은 견습생들의 역할 차이를 첫 수거 현장의 행동으로 보여 준다. 작업장 장비걸이에 검·방패·갈고리·중량 공구가 자연스럽게 함께 있다. 설명 대사로 직업을 가르치지 않는다.

PG-CAST-CONTINUITY

적은 수의 반복 인물이 사건 전후의 생활 변화를 보여 준다

  • 각 대지역은 사건 결정을 내리는 핵심 NPC, 생활 영향을 받는 핵심 NPC와 지역을 오가는 연결 인물 한 명을 기본 밀도로 사용한다. 이름만 다른 한두 줄 안내 NPC를 늘리지 않는다.
  • 핵심·연결 NPC는 고유한 머리, 복장, 도구 silhouette, 작업 동작과 말투를 가지며 사건 전·진행 중·해결 후에 위치·작업 상태·복장 손상·대사가 상황에 맞게 변한다.
  • 주인공, 라이벌, 고물상인처럼 역할이 바로 읽히는 호칭을 대사·HUD·장면의 같은 인물에 일관되게 사용한다. 이름을 바꾸더라도 저장된 진행이나 인물의 사건 관계가 달라지지 않는다.
  • 배경 인물은 생활감을 만들되 중요한 story 설명을 맡지 않아 플레이어가 기억할 사람을 불필요하게 늘리지 않는다.

PG-STORY-DELIVERY

이야기는 현장 말풍선으로, 하단 UI는 할 일과 조작으로 전달한다

  • 핵심 장면은 character 머리 위 말풍선으로 진행하며 필요한 순간에만 잠깐 조작을 제한한다. 일반 NPC 대화는 가까이서 jump/상호작용으로 시작하고, 이동 중 짧은 대화는 조작을 막지 않는다.
  • 주인공 독백은 새 장소·수상한 물체·중요한 선택을 발견했을 때만 머리 위에 짧게 나타난다. 중요한 대화는 기록에서 다시 볼 수 있지만 기록 UI가 현재 장면을 대신하지 않는다.
  • 하단 UI는 “수거장으로 이동”, “항구에서 승강기 cable 찾기” 같은 현재 할 일과 필요한 조작만 짧게 표시한다. 세계관·감정·사건 경위를 설명하지 않는다.

탐험 → 1~3개의 짧은 말풍선 → 문제 확인 → 전투/탐색 → 환경 변화 → 짧은 후속 반응을 기본 밀도로 삼는다.

4. 게임 진행 / D-30

한 달의 플레이 흐름

  1. Plan
    작전 지도에서 경로·예상 시간·우회 거리를 비교한다.
  2. Travel
    실제 연결로 끝에서 1구간 장거리 이동을 확정한다.
  3. Help
    주목표와 최대 두 연결 이슈를 따라 여러 지역의 생활 문제를 잇는다.
  4. Fight
    수거 유닛·산업기계와 Boss를 기존 기본기로 공략한다.
  5. Reconfigure
    기계를 분리하고 마지막 작업으로 경로를 막는다.
  6. Assemble
    D-DAY 경로와 차고의 대항 병기 외형을 갱신한다.

PG-OPEN-CAMPAIGN

다섯 대지역을 교차하는 약 10시간 캠페인을 원하는 순서로 해결한다

  • 다섯 지역은 처음부터 방문 가능하고 필수 부품 다섯 개를 모두 회수해야 D-DAY 전 최종전을 시작할 수 있다.
  • 기본 캠페인은 약 10시간, 부품 하나는 약 2시간의 중심 흐름을 제공한다. 한 번에 의미 있게 진행되는 것은 현재 주목표 하나와 연결 이슈 최대 두 개이며 다섯 지역의 모든 요청을 처음부터 한꺼번에 쌓지 않는다.
  • 부품 흐름은 독립된 지역 chapter가 아니다. NPC 말풍선 → 상태 확인 → 이동·전투 → 다른 지역의 사람·시설·기술이 필요한 실제 사건 → 원래 지역 귀환 → Boss → 대체 설비/마지막 작업 → 기계 분리 → 회수 → 경로·로봇 갱신으로 이어진다. 다른 지역 방문은 단순 배달이 아니라 새 인물, 탐색, 전투 또는 지역 상태 변화를 포함한다.
  • 대표 굴착기 흐름은 광산 구조 중 대형 승강기 cable 필요를 발견해 항구의 점거된 crane 일부를 복구하고 cable을 확보한 뒤 광산으로 돌아와 구조와 굴착기 회수를 끝낸다. 항구의 다음 문제와 온실 기술자 연결도 이 과정에서 자연스럽게 열린다.
  • 플레이어가 먼저 군수 인장을 해제하면 지역 기계가 주민과 마지막 작업으로 실제 진행로를 끊어 고대 병기가 우회한다. D-DAY 변화는 임의 보상이 아니라 지도에 그린 우회 거리와 일치한다.
  • 각 지역의 부품은 군수 인장을 해제하고 주민과 마지막 작업을 마친 뒤에만 회수한다. 부품 획득 자체가 아니라 그 작업으로 생긴 실제 경로 차단만 D-DAY 진로를 바꾼다.
  • 해결 전후 설비는 맵에서 작동/분해 상태가 바뀌고 부품은 회수 순서와 무관하게 차고 로봇 외형에 누적된다.
  • 주 흐름을 집중하면 전체 D-DAY 여유의 약 75~80%를 사용해 최종전에 도달한다. 남은 시간은 탐색·서브 이슈·인챈트와 몇 번의 실수를 허용하되 큰 실수를 반복하면 실제 게임오버가 된다.

PG-CAMPAIGN-TIME

의미 있는 선택으로만 D-DAY가 흐른다

  • 하루는 아침·낮·저녁·밤 네 구간이며 HUD는 현재 날짜·시간대·D-DAY를 작고 명확하게 표시한다.
  • 장거리 지역 연결로, 완전 회복 캠프/숙박, KO 거점 복귀와 핵심 사건 확정만 시간을 소비한다.
  • 대화, 구매, 인벤토리, 즉시 인챈트, 일반 전투, 지역 내 탐색·Room 이동과 offline 시간은 무료다.
  • 장거리 이동은 실제 도로 끝에서 목적지와 1구간 비용을 알리고 짧은 이동 연출 뒤 공간적으로 이어지는 연결 Chunk로 보낸다.
  • 핵심 사건은 총 예상 시간과 성공 뒤 바뀌는 우회 경로를 시작 전에 비교하고, D-DAY를 넘기는 행동은 경고 뒤 확정할 수 있다.
  • D-DAY 0은 예외 없이 조작 잠금 → 지도상 수도 도착 → 마을 파괴 연출 → 게임오버로 이어진다.

5. 작전 지도 / 지역 이동

PG-OPERATION-MAP

작전 지도에서 한 달 전체를 판단한다

  • 게임 MENU를 짧게 누르거나 고물상 벽 지도를 조사하면 같은 전체 작전 지도가 열린다.
  • 지도는 현재 위치, 지역 연결로, 고대 병기 위치·방향·도착 예정, 사건 상태, 예상 이동/사건 시간, 성공 뒤 실제 우회 거리, 부품과 완성도를 표시한다.
  • 고대 병기 표시는 실제로 시간을 소비한 확정 action에서만 이동하며 변경된 경로와 D-DAY 원인을 함께 보인다.
  • MENU 1초 hold의 개발자 panel과 짧은 작전 지도 activation은 서로 중복 실행되지 않는다.

6. 전투 시스템

PG-COMBAT-CONTROL

검·방패 기본기와 현재 전투 감각을 유지한다

  • 이동, jump, guard, 방향 roll과 Basic/Strong 두 공격이 desktop·touch 공통 command grammar를 이룬다.
  • Stamina, just guard 뒤 Basic 전용 방패 반격, damaging-hit-confirm cancel, Strong guard break·startup interrupt와 shield/Boss posture를 유지한다.
  • 구르기는 머리와 어깨가 먼저 내려가고 골반이 어깨 위로 넘어가며 두 발이 공중에서 몸 위를 지나는 전방 한 바퀴 회전이다. 접힌 몸이 진행 방향으로 계속 넘어간 뒤 발이 땅을 받고 달리기로 연결된다. 장비는 몸에 붙어 함께 회전하며, 회피 판정과 이동 거리를 바꾸거나 숙였다 일어나는 동작으로 대신하지 않는다.
  • 공격 가능 범위, guard 가능 여부, 강공 준비와 약점은 몸체·가동 부위·예비 동작으로 읽히며 text 색만 판정 근거로 삼지 않는다.
  • 공격별 최대 도달 범위·유효 시간·이동은 게임 규칙으로 먼저 정해진다. 그 범위와 시간 안에서 보이는 유효 무기가 적의 신체/약점/장갑/방패에 실제로 닿아야 피해 또는 해당 방어·무적 반응이 발생한다. 정해진 범위 안이어도 검이 닿지 않으면 빗나가고, 그림이 지나치게 길어 최대 범위 밖에 닿아도 피해가 발생하지 않는다. 머리·몸·팔다리·약점·장갑·방패의 의미가 그림으로 읽히며 작은 장식이나 잔상 끝을 몸으로 오인하지 않는다.
  • 대항 병기 최종전도 같은 이동·공격·guard·stamina·combo grammar를 확대해 사용하며 별도 미니게임이 되지 않는다.

공격은 몸 옆 낮은 준비에서 골반·흉곽이 먼저 회전하고 팔·손목이 뒤따르는 빠른 횡/사선 베기다. 검을 머리 위로 크게 올리는 generic windup을 기본으로 하지 않는다. 접촉 뒤 follow-through와 후반 감속으로 무게를 읽힌다.

7. 장비 시스템

전투와 현장 작업에 쓰는 장비 조합

검은 시스템이 아니다. 검은 장비 시스템의 첫 번째 구현이다. 기본 장비는 현장 절단검(Field Cutter) + 현장 방호판(Field Shield)이며 기사검·장식 방패가 아니다.

슬롯 역할
주무기 Basic/Strong의 성격, reach와 stamina 부담
방패 독립 장착. Guard/Just Guard/반격과 잔해·압력 방호
투구 독립 방어구
몸통 독립 방어구
신발 독립 방어구
도구 탐험·수거·측량·현장 작업 보조

장비가 달라도 Move/Jump/Roll/Basic/Strong/Guard 입력 문법을 최대한 유지한다. 양손 장비는 방패 사용에 제약이 있다. 장비 화면은 이름·분류·슬롯·손 사용과 Basic/Strong/Guard, reach/stamina/posture 특성 및 현장 기능을 보여 준다.

절단검은 케이블/얇은 판금 절단·소형 기계 제압, 방호판은 잔해/압력 차단·지지에 쓰인다. 장비를 단순한 진행 열쇠로 만들지 않는다. 강제 장비 gating은 미정이며 기존 자유 캠페인을 유지한다. 도구의 빠른 현장 교체/사용 방향은 유지하되 모든 도구나 새 전투 교체키를 지금 확정하지 않는다.

상세 제작·저장 계약은 장비 시스템 명세에서 읽는다.

8. 성장 / 강화 / 인챈트

PG-SCRAP-GROWTH

생활권의 고철 장비로 전투 선택을 확장한다

  • 무기·인챈트 NPC는 고철 병기와 마력 기계를 다루는 생활권 인물이며 transaction은 실제 대화 안에서만 열린다.
  • 인챈트 가능한 현장 장비의 단일 인챈트, 속성 affinity와 단계 성장, 장비별 speed·reach·posture trade-off는 현재 combat grammar를 확장한다.
  • 주인공 장비는 짧은 작업상의·크로스스트랩·작은 공구 주머니·임시 수리 흔적을 유지하고 회수 지역 재료가 누적되며 무관한 판타지 갑옷이 되지 않는다.

Equipment는 어떻게 싸우는가, Combat Skill은 같은 문법에서 얼마나 숙련되었는가다. 지상/공중 combo·공중 행동·loop cancel·피해 성장은 공통 숙련으로 유지한다. 상점/대장간·재료·제작/파생·강화·인챈트·탐험/퀘스트/보스 보상을 사용하며 무작위 loot farming으로 전환하지 않는다.

세트 시너지

같은 세트의 장비를 일정 수 장착하면 부분/전체 보너스가 적용된다. 조건과 효과는 처음부터 공개되어 예측 가능한 빌드 선택이 된다.

특수 시너지와 도감

서로 다른 장비·세트·계통을 교차한 의도된 조합이다. 같은 세트 조각 수와 별개이며 모든 조합을 자동 생성하지 않는다. 단순 숫자보다 Just Guard 후 공격·Roll 연결·Strong 성격·밀기/당기기·현장 기능 결합 같은 플레이 변화에 가치를 둔다.

  1. 관련 장비를 소유한 적 없으면 관련 특수 시너지를 노출하지 않는다.
  2. 관련 장비를 보유한 이력이 생기면 이름/조건/효과 없이 ??? 슬롯을 볼 수 있다. 정답을 암시하는 텍스트 힌트는 없다.
  3. 정확한 조합을 실제 장착하면 발견한다.
  4. 이후 이름·정확한 조건·효과를 영구 공개하고 저장 후에도 유지한다.

9. 지역

다섯 지역과 산업기계

다섯 지역은 처음부터 열려 있고 회수 순서는 자유롭다. 그러나 한 부품의 약 2시간 중심 흐름은 한 지역에서 닫히지 않고 다른 지역의 사람·시설·기술을 실제 사건으로 거쳐 다시 원래 지역으로 돌아온다. 각 사건은 해결 전후의 실제 설비와 지역 생활을 바꾼다.

폐광 산촌

붕괴 광산의 작업자를 구출하고 폐광이 결정된 보행식 대형 굴착기의 하체·구동부를 인수한다.

항구 조선소

수거대에게 점거된 조선소를 되찾아 마지막 선박 수리를 끝내고 쌍둥이 크레인의 유압 장치를 인수한다.

온실 평원

안전한 지열 설비를 복구한 뒤 불안정한 구형 고출력 동력로를 분리한다.

설산 교역로

옛 터널을 개통해 산길을 대체하고 필요 없어진 장갑 제설 열차 차체를 인수한다.

붉은 채석장

마지막 채굴과 안전 폐쇄를 끝내고 초대형 암반 절단기를 인수한다.

10. 몹 / Boss

PG-SCRAP-READABILITY

직업·소속·공격을 silhouette로 읽는다

  • 얇은 stickman 계열 인간형 비율 위에 직업별 작업복·도구·동작과 큰 장비 면을 얹는다.
  • 주인공은 작은 단순한 타원형 머리와 약 7등신의 길고 가는 팔다리, 짧은 상의와 바지, 대각선 스트랩, 넓은 검으로 읽힌다. 평상시에는 팔과 검을 낮게 두고, 공격할 때 몸의 무게 이동과 큰 베기 궤적이 명확하다. 기본·강공격은 검을 머리 위로 들어 올리지 않고 몸 옆의 낮은 위치로 검을 당긴 뒤 골반과 흉곽이 먼저 회전하고 팔이 뒤따라 몸 앞을 가로지르는 빠른 횡·사선 베기다. 접촉 뒤에는 follow-through와 감속이 읽힌다. 과도한 머리·머리카락·고글·앞치마 면으로 신체 비율을 가리지 않는다.
  • 고물상 주인, 광부, 조선공, 온실 기술자, 열차 승무원과 채석공은 복장·도구·말투·행동이 실제 일에서 나온다.
  • 적은 동원 신호를 받은 산업기계, 설비 기생/도둑 기계 생물과 현장을 먼저 차지하려는 인간 고철 수거반으로 이루어진다. 인간 수거반은 작업복·공구·보호구와 현장 선점 동기로 주민·라이벌과 구별되며, 지역 Boss는 지역 사건과 기계 기능을 전투 동작으로 확장한다.
  • 각 지역 조우는 비인간 고유 몹 넷, 인간형 고유 몹 하나, 현지 동원 기계·엘리트·Boss를 포함한 여덟 실루엣을 기본으로 하며, 전체 전투의 인간형은 약 20~25%만 차지한다. 소형 군집·사족·다족·비행·지중·수중·벽/천장·차륜/궤도·고정 환경형과 비정형 대형을 섞고, 야생동물·동원 기계·실제 인간은 서로 다른 적대 조건과 종료 반응을 보인다.
  • 작업인형은 사람의 머리·몸통·두 팔·두 다리가 읽히되 지역 작업 도구로 한쪽 신체가 크게 비대칭이다. 실제 인간 적은 항복하거나 도주하며 죽는 연출을 쓰지 않고, 인간형 결투는 비인간 지역 Boss를 대체하지 않는다. 띄우기·부위 파괴·추락·stagger는 체형에 따라 명확하며 설명 없는 무적과 상시 슈퍼아머를 쓰지 않는다. 일반 이동과 중요한 액션 모두 인물의 체형·장비·역할을 유지한다. 인간은 작은 머리와 가는 팔다리라는 공통 언어 안에서도 어깨·골반·팔다리·몸통·자세가 구별되며, 구조가 다른 기계를 같은 인간 몸의 길이만 바꿔 표현하지 않는다. 중요한 공격과 구르기는 승인된 reference/key pose의 실루엣과 무게 이동을 지킨다.
  • 지역별 색·산업 재료와 공통 리벳·판금·케이블·작업용 천·수리 흔적이 최종 로봇에서 다시 읽힌다.
  • 구현 전에 주인공·핵심 NPC·적 계열·Boss의 정면/측면 silhouette, 대표 pose와 실제 화면 크기 구분 기준을 시각화해 비교한다.

현재 인물·적 목록과 필요한 상태는 몹/Boss 제작표에 연결한다. 아직 정의되지 않은 적 종류를 그럴듯하다는 이유로 추가하지 않는다.

11. 대항 병기

PG-FINAL-BATTLE

다섯 산업기계가 보이는 조립식 로봇으로 결전한다

  • 굴착기 다리, 크레인 팔, 동력로, 제설 열차 장갑과 채석장 절단검의 원래 색·형태가 완성품에서 구분된다.
  • 최종전은 배경·적·Player를 거대 전장 규모로 바꾸되 현재 전투 입력과 판정 원칙을 유지한다.
  • 고대 병기는 옛 군수 명령을 문자 그대로 실행하는 융통성 없는 병기다. 제어핵 응답 없음, 중앙 지휘소 복귀와 동원 신호만 짧고 사무적인 낡은 방송으로 알리고, 무거운 신체 공포가 아니라 캐주얼하게 과장된 불완전 조립과 수거 행동으로 위협과 웃음을 함께 만든다.
  • 결전은 장갑과 무기를 파괴해 제어부를 노출한 뒤 우리 로봇의 두뇌로 사용한 첫 제어핵을 다시 고대 병기에게 설치하고 정지 명령을 내려 끝낸다.
  • 후일담에서 대항 병기는 다섯 지역 산업기계로 돌아가고 제어를 되찾은 고대 병기는 왕국 복구용 중장비가 된다. 주인공과 라이벌은 사고를 낸 견습생에서 왕국 공식 수거팀으로 인정받아 첫 선택과 책임을 닫는다.

12. 그래픽 / 화면 구성

기준은 실제 게임에서 구현 가능한 밝고 단순한 Flat Design이다. 고밀도 컨셉 일러스트·잡동사니·러프한 손그림을 지양한다. 밝은 자연광과 sky value, 더 밝은 원경, 지역색과 적당한 따뜻한 포인트로 생활감을 만든다. 저채도를 칙칙한 폐허로 해석하지 않는다.

PG-VISUAL-FIDELITY

고철 컷아웃과 벡터 셀 아트가 유료 게임의 기준 장면을 만든다

  • 정돈된 레오곡 계열의 2D 액션 RPG처럼 작은 캐릭터와 넓은 생활형 산업 세계를 보여 준다. 특정 작품의 개별 캐릭터를 복제하지 않으며, 안정적인 실루엣·단순하고 명확한 벡터/폴리곤·큰 면의 3~4단계 셀 명암을 사용한다. 삐뚤빼뚤하거나 러프한 손그림 느낌을 지양한다. 전체 저채도를 공유하면서도 폐광의 갈색/황토/경고 황색, 항구의 청회색/청록/녹슨 적색, 온실의 황동/탁한 녹색/수증기 백색, 설산의 백청/남청/열선 주황, 채석장의 적철/짙은 갈색/먼지 베이지가 스크린샷만으로 구분된다. 색만 바꾼 같은 장소처럼 보이지 않고 형태·재질·생활 설비도 지역을 식별하게 한다.
  • 기본 화면은 세계와 스케일을 우선한다. 인간형 높이는 실제 desktop gameplay viewport의 약 18~22%를 유지하고 모바일에서도 작은 인물과 넓은 장소의 관계를 보존한다. 한 화면에서 생활 공간과 대형 기계/랜드마크가 함께 읽힌다. 일반 전투가 시작됐다고 카메라가 갑자기 줌인하지 않으며 실루엣·외곽선·배경 대비·공격 예고·무기 궤적·효과로 전투를 읽는다. Boss 등 명시된 특별 연출에서만 framing 예외를 둔다. 얇은 몸체에서도 작은 머리·작업복·스트랩·관절·도구 형태가 실제 화면 크기로 구별된다.
  • 캐릭터 면과 외곽선은 움직여도 연속되고 깨끗하다. 깊이 가림을 사용하되 면에 구멍, 뒤쪽 선의 관통, 원색 반점과 지글거리는 면 겹침이 생기지 않는다. 피부·천·금속은 적은 수의 일관된 색과 명암 덩어리로 구분한다.
  • 게임·그래픽 검토실·테스트 플레이는 폴리곤 표현으로 통일한다. 저해상도 픽셀화, 화면 좌표 snap, posterization·alpha threshold 후처리와 정수 배율 확대를 적용하지 않는다. 윤곽·명암·재질 detail은 원본 geometry와 조명에서 정의하며 화면 크기에 맞춰 선명하게 출력한다. 깊이 가림과 보이는 외곽선은 유지하고 정지/이동 모두 배경 위에서 검증한다.
  • 생활 공간의 주요 길과 중요한 상호작용 주변은 깨끗하게 읽힌다. 배경 detail은 의미 있는 덩어리로 묶고 의도적인 빈 공간을 두어 장식이 gameplay silhouette를 덮지 않는다. 장소는 시각적 목적·랜드마크·사건이 이어지는 연속된 공간으로 보이며 장면 구성 단위 때문에 화면이 끊기지 않는다. 멀리서 본 같은 랜드마크가 가까워져도 동일한 기계로 인식되고, 필요한 세부 표현의 전환이 깜빡이거나 갑자기 다른 물체로 바뀌는 느낌을 만들지 않는다.
  • 태양·달·전등·용광로·공격 effect는 위치·방향·세기·범위를 가진 광원이다. 폴리곤 면, 광원 관계, 재질 반응과 장애물 차폐를 계산해 3~4단계 cell 명암으로 양자화하고, 접지·투영 그림자와 금속·천·흙·돌의 서로 다른 반응을 함께 보인다.
  • 타격은 준비 pose → 접촉 섬광 → 짧은 hit stop → 타격 방향 camera 이동 → 반동·knockback → 잔상·파편 감쇠로 읽힌다. 위력이 클수록 강조하며 reduced motion에서도 hit stop, 자세 반동과 접촉 effect는 유지한다. 일반 피격·guard·just guard·무적·강공 준비와 enchant 속성은 색이 아니라 pose, shape, particle와 trajectory가 먼저 구분한다.
  • HUD는 얇은 판금 frame과 계기판 형태의 체력·stamina·D-DAY를 화면 가장자리에 작게 유지하고 위험·guard break·시간 변화 때만 확장한다. 장식은 플레이 영역과 공격 예고를 가리지 않으며 MENU short와 developer panel long hold의 경계를 유지한다.
  • 주인공·NPC·일반 적·대표 지형·전경과 배경·동적 광원·공격과 피격·HUD가 하나의 같은 장면에서 위 규칙으로 읽히고, 최종 제품의 모든 지역·인물·적·Boss에도 같은 규칙을 사용한다. 기존 학원 fantasy presentation과 새 고철 cutout presentation을 섞어 남기지 않는다.

미술과 이야기의 공통 제약

  • 세계의 기본 정서는 오래된 설비를 고쳐 쓰며 생업을 이어가는 생활형 산업 왕국이다. 낡음은 멸망, 고철은 쓰레기, 산업기계는 디스토피아를 뜻하지 않는다. 폐광의 레일/굴착기/지지대, 항구의 크레인/도크/케이블, 온실의 배관/동력로, 설산의 제설 열차, 채석장의 절단기는 주민의 기반시설과 작업 도구다. 옛 군수 규격은 이 생활 기계에 남은 잠금·인장·접속 방식이며 세계 전체를 호러/미스터리 미술로 바꾸지 않는다. 재난의 이야기와 유머를 유지하되 감염·신체 개조·잔혹한 body horror·과도한 음울함을 사용하지 않는다.
  • 도입과 지역 변화는 별도 영상이 아니라 polygon render object, camera, shake, 말풍선, combat, map patch와 저장 flag로 플레이 안에서 표현한다.
  • 구현 가능한 단순한 polygon 면과 정돈된 flat vector 윤곽을 함께 사용한다. 저채도 장면 안에서도 silhouette, material, light와 기능적 accent가 정보를 분리하며 단순한 회색 바닥이나 원형 밝기 overlay를 완성된 광원 표현으로 사용하지 않는다.
  • 배경만 바꾸고 기존 학원 판타지형 Player·교관·마법 생물·Boss를 남기지 않는다.
  • 낮은 확률 farming, 시간에 따른 필수 경로 폐쇄, portal마다 시간 청구와 세계지도 순간이동을 핵심 진행으로 사용하지 않는다.

13. 확정 / 미정

확정: 생활형 산업 왕국, 수거·복구 역할, 기본 현장검+방호판, 독립 6슬롯, 공통 전투 입력, 5지역 자유 캠페인, 공개 세트와 발견하는 교차 시너지, 작고 명확한 인물·넓은 세계.

미정: 출시 최종 무기군 수, Breaker/Pole 실제 콘텐츠, 전투 중 즉시 무기 교체, 장비/장비군별 skill tree, 강제 Field gating, Shield/Armor enchant, 최종 특수 시너지 수와 모든 도구 종류.

플랫폼 · 검토 · 복구

PG-PLATFORM-ACCESS

Desktop과 mobile에서 같은 캠페인을 수행한다

  • 메인 메뉴는 모바일 가로·세로 화면의 실제 보이는 높이와 안전 영역에 맞춘다. 제목·게임 시작·모바일 시작·현재 버전·업데이트 확인과 적용을 과도한 확대나 잘림 없이 읽는다. 데이터 안내는 접어서 열 수 있고, 좁은 높이에서도 주요 버튼에 접근할 수 있다.
  • Keyboard와 touch는 같은 gameplay intent와 command 결과를 만들고 operation map과 대화를 keyboard로도 사용할 수 있다.
  • Mobile landscape와 desktop에서 HUD, 목표, 작전 지도, 말풍선과 control이 서로 가리지 않는다.
  • 개발자 panel은 stable intro/region/robot/last-segment/game-over/final-battle 상태를 같은 page에 즉시 적용하고 URL로 복원한다.
  • 시작 화면의 눈에 보이는 디버그 모드 버튼을 한 번 눌러 지도 해금 전에도 같은 패널에 진입한다. 메인 메뉴의 게임 제목과 게임 화면의 MENU/MAP을 1초 길게 누르면 같은 패널이 열린다. 시작 구간의 MENU를 짧게 누르면 메인 메뉴로 돌아가고, 지도 해금 뒤 MAP을 짧게 누르면 작전 지도를 연다. 길게 누른 동작이 짧은 동작까지 중복 실행하지 않는다.
  • 게임과 모든 검토 화면은 같은 폴리곤 renderer와 immutable state·판정 원인을 사용한다.

PG-GRAPHICS-REVIEW

전체 그래픽을 같은 화면에서 검토하고 정확한 피드백 대상을 복사한다

  • 외형·본 연결·애니메이션·프레임·조명은 그래픽 검토실에서, 실제 조작·판정·카메라와 지형 관계는 저장과 분리된 테스트 플레이에서 확인한다. 별도의 렌더 연구실을 두지 않고 디버그 패널은 장면 선택과 두 작업으로 들어가는 입구가 된다.
  • 유형 탐색과 선택 후 자주 쓰는 동작은 선택 위치 주변의 원형 메뉴에서 연다. 큰 분류에서 하위 유형·지역·방을 거쳐 모든 최종 리소스까지 찾기 안에서 선택한다. 트리 안에서 이름·ID로 하위 항목을 검색하고 상위 경로로 바로 돌아갈 수 있다. 페이지 이동은 별도 이전·다음 버튼을 사용하며 항목 방향을 고정한다. 긴 이름은 선택 설명에 표시한다. 썸네일 목록은 보조 경로다. 중심과 주변 버튼은 가까이 배치하고 하위 메뉴에서도 중심 위치를 유지한다. 원형 메뉴는 화면 밖으로 잘리지 않고 뒤로·닫기와 keyboard/touch 조작을 제공한다. 재생·동작 선택·조건 복사에 긴 화면 스크롤을 요구하지 않는다. 상세 프레임 시트와 본/메시·속도·조명 진단은 필요할 때 펼친다.
  • 실제 테스트 배치가 있는 대상은 선택을 유지한 채 테스트 플레이로 갔다가 같은 리소스·동작·프레임으로 돌아온다. 아직 실전 동작이나 배치가 없는 견본을 다른 대상으로 바꿔 실행하지 않고 지원 범위를 명확히 알린다. 테스트 시작·진행·재시작과 복귀는 원래 저장·복구 지점을 변경하지 않는다.
  • 몹 제작 기준으로 인간형·짐승형·비행형·기계형 각각 한 개의 움직이는 대표를 검토한다. 각 유형은 서로 다른 몸 구조와 이동·공격을 보여 주며, 주인공이나 기존 실전 몹을 승인되지 않은 공통 체형으로 일괄 대체하지 않는다.
  • 승인된 reference에 맞춰 체형과 부위를 수정해도 일반 동작을 재사용하고 중요한 액션의 key pose를 보존한다. 외형 변경 때 모든 프레임을 다시 만드는 부담을 줄이며, 필요한 부위나 극단적 전신 pose를 선택적으로 교체해도 자세·접촉·장비 연결이 일관된다. AI가 의미 있는 원본 구조를 쉽게 수정할 수 있어야 한다. 검토실 등록, 제작 계약 확정, reference 승인과 runtime 검증은 서로 다른 상태로 표시한다.
  • 개발자 모드에서 주인공·NPC·모든 현재 몹, 무기·장비, 배경·전경·지형·건물·설비·소품, 이펙트와 UI를 종류별로 찾는다. 비활성 변형을 포함한 현재 목록과 의도적 제외·아직 없는 동작을 명확하게 구분한다.
  • 정적 리소스는 thumbnail·실제 크기·확대로 확인한다. 움직이는 리소스는 동작별 행의 연속 frame strip, 정상 속도 재생·정지·이전/다음 frame을 제공한다.
  • 배경·건물·지형은 개별 형태와 실제 장면의 배치·조명·가림을 함께 확인한다. 검토 그림과 UI는 실제 게임의 동일한 리소스와 표현을 사용한다.
  • 현재 리소스·동작·프레임의 변하지 않는 ID와 이름, renderer·배치·조명·확대·방향·재현 URL을 읽고 명시적인 복사 동작으로 관리 대화에 붙여넣는다. 자동으로 피드백을 전송하지 않는다.
  • desktop과 mobile에서 모든 종류와 제어에 접근하고 URL로 같은 선택과 프레임을 다시 연다. 일반 게임 화면에는 검토용 디버그 정보가 노출되지 않는다.

PG-RECOVERY

시간 선택과 게임오버를 복구 가능하게 저장한다

  • 매일 아침, 핵심 사건 완료 직후와 시간 소비 action 확정 직전에 복구 가능한 저장을 만든다.
  • 게임오버 뒤 최근 날짜 또는 더 이전 핵심 사건 완료 save를 골라 재개하며 세계 안의 시간 되감기로 표현하지 않는다.
  • 저장 실패·손상, Room 전환 실패, KO와 반복 trigger는 숨은 시간 소비·보상 중복·stale input을 만들지 않는다.
  • PC와 모바일 메인 메뉴에 저장 초기화 버튼을 바로 표시한다. 호환되지 않는 개발 저장으로 업데이트가 막혀도 같은 버튼으로 복구할 수 있다. 초기화는 기존 진행과 복구 지점 삭제를 확인한 뒤 실행하며 취소하면 그대로 보존한다. 성공하면 새 진행을 저장하고 업데이트를 다시 적용할 수 있으며 실패하면 현재 상태를 유지하고 알린다.

PG-PWA-OFFLINE

한 번 정상 로딩한 모바일 게임은 설치·오프라인·안전한 갱신까지 이어진다

  • 앱 시작, 화면 복귀와 메뉴의 명시적인 업데이트 확인에서 새 배포를 신속하게 확인한다. 현재 버전·서버에서 발견한 버전·다운로드 중·적용 준비 완료·확인 실패를 구분하고, 최초 설치한 동일 버전을 다른 창의 업데이트로 오인하지 않는다. 준비된 업데이트 확인·파일 준비·저장·버전 전환·새 화면 로딩의 진행 상태를 움직이는 표시와 단계 문구로 즉시 알린다. 실제 진행률을 모르면 퍼센트를 꾸미지 않는다. 적용 중에는 중복 조작을 막고 실패 시 진행 표시를 종료하여 재시도를 안내한다. 업데이트는 메뉴에서 한 번의 명시적 적용으로 저장 후 전환하며, 실패하면 현재 버전으로 계속 플레이하고 재시도할 수 있다.
  • 업데이트를 준비하는 동안 기존 화면은 그 버전의 파일만 사용한다. 다른 창에서 새 버전을 적용해도 열린 화면에 서로 다른 릴리스의 파일이 섞이지 않으며, 현재 진행을 저장한 뒤 다시 여는 행동을 안내한다.
  • Android Chromium과 iPhone/iPad Safari에서 홈 화면 앱으로 설치할 수 있다. 설치 가능한 환경의 메인 메뉴에만 앱으로 설치를 보이고, Android는 사용자 입력으로 시스템 설치를 요청하며 iPhone/iPad는 공유 → 홈 화면에 추가의 짧은 안내를 연다.
  • 설치 앱은 standalone 창과 가로 방향을 우선 사용한다. 게임 시작 시 지원되는 기기에서만 방향 잠금을 요청하며, 기본 강제 전체화면은 사용하지 않는다. HUD와 조작계는 safe-area를 피해 노치·상태 표시줄·홈 인디케이터에 가려지지 않는다.
  • 온라인에서 한 번 정상 로딩한 현재 배포본은 메뉴, 모든 게임 module·화면·저장·복구와 설치 asset을 하나의 versioned cache로 준비해 네트워크 없이 계속 플레이한다. 최초 방문이 오프라인이면 빈 화면 대신 연결 필요와 재시도 행동을 보여 준다.
  • 새 버전은 플레이를 중단하지 않고 완전한 새 cache가 준비된 뒤 메뉴에만 알린다. 사용자가 적용하면 최신 진행과 recovery slot을 먼저 저장하고 waiting worker를 한 번 활성화해 한 번만 새로고침한다. 실패한 갱신은 기존 정상 cache와 저장을 유지한다.
  • 주인공 고글·공구 가방·검 silhouette가 작은 크기에서도 읽히는 일반·maskable icon과 standalone launch asset을 제공한다. cache와 게임 진행 저장은 분리되며 삭제 가능한 browser data 경계는 도움말에서만 짧게 알린다.
